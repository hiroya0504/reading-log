# AIレビュー（検出→検証の2段構成）

このスキルは、自分で直接レビューせず、**検出エージェントと検証エージェントを呼び分ける司令塔**として動く。
自分でコードを読んで指摘を追加・修正してはいけない。削除してよいのは、手順 3 の判定と手順 4 の統合によるものだけ。

ルール定義: `.claude/skills/ai-review/references/rules.md`（以下「ルール定義」）。仕組みと運用は `docs/ai-review.md`。

## モード

- **CIモード**: プロンプトに `MODE: ci` と `PR NUMBER` が含まれる場合。結果をJSONとして最終出力に返す。**PRへの投稿はしない**（投稿はワークフローの後続ステップが行う）。
- **ローカルモード**: それ以外。結果を画面に表示するだけで、どこにも投稿しない。

## 手順

### 1. 差分の範囲を決める

- CIモード: `gh pr diff <PR NUMBER> --name-only` で変更ファイル一覧を取る。
- ローカルモード: `git diff --name-only origin/main...HEAD` と `git diff --name-only`（未コミット分）を合わせる。

次の条件を**すべて**満たすファイルだけを対象にする。

- `backend/src/main/java/` 配下の `.java` ファイル
  - テストコード（`src/test/`）はここで外れる。必要になったらルールを追加する
  - 自動生成コード（`build/`、`generated/` 配下）もここで外れる
- 作業ツリーに存在する（削除されたファイルは除く）

対象ファイルがなければ、指摘0件として手順5へ進む。

### 2. 検出

`review-detector` エージェントを呼ぶ（Agent ツール、`subagent_type: review-detector`）。
対象ファイルが8個を超える場合は、ファイルを8個以下のグループに分けて**並列に**呼ぶ（1つのメッセージで複数の Agent 呼び出し）。

渡す内容は次の3つだけ。変更の意図や、危なそうな箇所の見立ては渡さない。

- 対象ファイル一覧
- 差分の取得方法（CIなら `gh pr diff <PR NUMBER>`、ローカルなら `git diff origin/main...HEAD` と `git diff`）
- ルール定義のパス

各エージェントが返したJSONの `findings` をすべて集める。JSONとして読めない応答は、そのグループの検出に失敗したものとして扱い、最終出力の前に報告する（CIモードでは件数に含めない）。
この時点の件数を **検出件数**（`detected_count`）として控えておく。0件なら手順5へ進む。

### 3. 検証

集めた指摘**1件ごとに** `review-verifier` エージェントを1つずつ呼ぶ（`subagent_type: review-verifier`。並列で呼んでよい）。

渡す内容は指摘のJSON1件とルール定義のパスだけにする。**検出エージェントの思考過程や他の指摘は渡さない。**
検証役に先入観を持たせないため。

応答の1行目が、前後の空白を除いて `VERDICT: KEEP` と完全に一致するものだけを残す。
1行目がそれ以外の形式（`VERDICT: DROP`、空行、説明文など）なら DROP 扱いにする。

### 4. 集約

- 同じ `rule_id` で同じファイルの指摘が複数あれば、行番号が最も小さいものを代表の1件にし、他の該当行を `issue` の末尾に「同様の箇所: 58行目、73行目」のように追記する。
- 重要度順（high → medium）に並べる。同じ重要度の中では、ファイルパス、行番号の順。
- 件数の上限による絞り込みはしない（CIではワークフロー側で行う）。

### 5. 出力

#### CIモード

PRへの投稿や `gh` によるコメントは**行わない**。次の形のJSONを最終出力として返す。
スキーマは呼び出し側で指定されているので、それに従うこと。

```json
{
  "detected_count": 7,
  "findings": [
    {
      "rule_id": "DEF-001",
      "severity": "high",
      "file": "backend/src/main/java/com/example/readinglog/book/BookService.java",
      "line": 42,
      "issue": "同一クラス内の register() から REQUIRES_NEW 付きの saveHistory() を呼んでおり、プロキシを経由しないため新しいトランザクションが開始されない。",
      "suggestion": "saveHistory() を別の Bean に切り出し、そちらを注入して呼び出す。"
    }
  ]
}
```

- `detected_count`: 手順2の検出件数（検証前）
- `findings`: 手順3・4を経て残った指摘。0件なら空配列。検出役の `id` は含めない
- `file`: リポジトリルートからの相対パス
- `line`: 新しいコード側の行番号

#### ローカルモード

残った指摘を、ファイル名・行番号・ルールID・重要度・内容・修正案の形で一覧表示する。
最後に「検出 N件 → 検証通過 M件」を表示する。検出に失敗したグループがあれば、それも書く。
